# Sable

A desktop ADE (agentic development environment) for Claude Code and Codex, and OpenCode where it is installed. Vite + React 19 + TypeScript, shipped as an Electron app for Windows (`electron/main.ts`, page-drawn window controls in `src/app/WindowControls.tsx`). One process serves the UI and hosts the bridge.

## Commands

- macOS (experimental, written and checked without a Mac): `electron-builder` `mac` config in package.json (dmg + zip, ad-hoc signed, hardened runtime, `build/entitlements.mac.plist`, icon from `scripts/make-icon.mjs` → `build/icon.icns`), built by `.github/workflows/mac.yml` on macOS runners (one per chip; it also starts the packaged app once and uploads a screenshot). Shell differences live in `electron/main.ts` (Sable menu with Settings, File, Edit, View, Window; closing the window keeps the app in the Dock, `activate` reopens it; `pageKey` menu items that send the page's own shortcut) and `server/util/login-env.ts` (a Finder-launched app has launchd's bare PATH: the login shell is asked for its PATH before the bridge starts). Updates: `server/services/update-mac.ts` (zip, a shell script swaps the bundle). The page's `data-desktop='darwin'` rules in `app.css` make room for the traffic lights. Never touch signing identities or add Windows-only calls without a `process.platform` guard.
- `pnpm dev` starts Vite with the bridge attached (WebSocket at `/__sable`). It runs on the real profile (`~/.sable`): every Demo session a test starts there lands in the owner's sidebar. For tests and screenshots start `node scripts/dev-test.mjs` instead (same server on a throwaway data folder, `%TEMP%/sable-dev-home`). A dev server is usually already running on http://localhost:5173 (or 5174 when that port was taken) — reuse it, never start a second one. `scripts/shot.mjs` finds it by itself (127.0.0.1 first, where the test server alone listens, then localhost).
- `pnpm exec tsc --noEmit -p tsconfig.json` type-checks everything. `pnpm exec vitest run` runs tests. A test that puts a fake CLI on PATH deletes `SABLE_CLAUDE_BIN` first and puts it back after: the desktop shell sets it for its children, so a run started from inside Sable would otherwise ask the real Claude Code.
- Smoke scripts: `pnpm exec tsx scripts/claude-smoke.ts`, `scripts/codex-smoke.ts`, `scripts/opencode-smoke.ts`. Real agent turns (these scripts, or any session with Claude Code, Codex or OpenCode) cost the owner's quota and need his say-so each time.
- `http://localhost:5173/?gallery` (dev only, `src/dev/Gallery.tsx`) shows every control primitive in every state.
- Performance: `node scripts/perf-headless.mjs [--label x] [--only a,b]` measures work per interaction against the dev server, headless (results in `scratch/speed/`); `node scripts/perf-electron-idle.mjs` reads the idle CPU of the built desktop app, off-screen (needs `pnpm desktop:build`). Never run `scripts/perf-electron.mjs` while someone uses the machine: it opens a visible window.
- Widget checks, headless: `scripts/widget-sandbox-check.mjs` (what a hostile widget can reach), `scripts/widget-stream-check.mjs` (a widget streaming in).
- Desktop builds: `pnpm desktop:pack` (unpacked, `release/`), `pnpm desktop:dist` (installer). For checks, build into another folder (`pnpm desktop:build && pnpm exec electron-builder --dir --config.directories.output=release-qa`); never touch `release-sable/`, the owner runs his copy from there.
- Driving the packaged app off-screen: start `Sable.exe --screenshot=<file> --wait=3600000 --eval=1 --remote-debugging-port=<port>` with `SABLE_HOME` and `SABLE_USER_DATA` pointed at new temporary folders and `SABLE_DEMO=1`. `--screenshot` keeps the window at -32000,-32000 and out of the taskbar; `--eval` enables the `sable` helpers; connect with playwright-core's `chromium.connectOverCDP` (add `--inspect=<port>` to reach the main process). Local recipes (git-ignored): `scratch/desktop/lib.mjs`, and `scratch/docs/lib.mjs` for shots at 1440x900 and 2x with an empty home. Never show, focus or maximise the window. For anything that may be seen, also point `USERPROFILE`, `CLAUDE_CONFIG_DIR` and `CODEX_HOME` at empty folders, or the real agents show the owner's accounts and usage. Kill what you start and delete the folders.

## Architecture

- `shared/protocol.ts` is the contract. The bridge owns all state; the UI is a view that calls RPC methods and applies events. Every provider is normalized into one timeline model (`TimelineItem`: user, text, thinking, tool, notice, turn). The UI never branches on provider id except for marks and colour.
- `server/` — bridge. `app.ts` (RPC handlers, sessions, accounts, prewarm), `core/runtime.ts` (SessionRuntime: timeline + prompts + the queue of messages sent mid-turn), `core/cache.ts` (DiskCache: last known sign-in and caps under `~/.sable/cache/`, served at start-up, refreshed in the background), `providers/` (`claude.ts` via the Agent SDK, `codex.ts` via `codex app-server`, `opencode.ts` via `opencode acp` (`opencode-acp.ts` the client, `opencode-map.ts` the mapping; listed only where OpenCode is installed, no accounts of its own, OpenCode Go's windows as its limits), `demo.ts` scripted; `widget-tool.ts` the `show_widget` tool both agents get; `browser-tool.ts` the Browser tab tools both agents get, `browser_read`, `browser_screenshot` and `browser_open` answered by the window that shows the session's Browser tab, off per session with `SessionOptions.browserTab`), `services/` (fs, git, terminal, memory, config, backdrop; `pulls.ts` pull requests from the Changes tab, pushed and opened with `gh` only on the person's click, and `core/commit-draft.ts` a commit message by the chat's own agent and account; `usage.ts` a read-only incremental scanner of the agents' transcripts for tokens by day, model, project and session; `limits.ts` plan limits per account with a short history per window, for pace), `accounts/` (`folders.ts` finds existing config folders by their listing only, `handover.ts` carries one conversation's transcript to another account).
- Accounts: each agent has the built-in default account plus extras (`AccountInfo`, own config dir under `~/.sable/accounts/`, or an existing folder used in place); sessions carry `accountId`, caps are keyed by provider + folder + account (`capsKey`). Sable never opens a file that holds a sign-in: auth and limits are asked of the CLIs (Claude's limits come from the SDK's usage request and each turn's `rate_limit_event`). UI in `src/features/accounts/` (`Switcher.tsx`, the sidebar footer's one row that fits the narrowest sidebar, 196px: the agent's mark, one name (the account's label when the agent has several, else its plan) and a small ring with how much of its most used window is used, the same figure its row in the menu shows; the tooltip has the plan, every window and its reset; its menu lists every agent's accounts, with the pointed-at one's limits beside it (one object in two panes: the same radius and rim, bottoms on one line); the menu's one check is the account in use (the open chat's own, on home the one the next chat starts on; `accountMark` in `accounts/model.ts`), and where new chats start, when that is another account, is a quiet dot; `ManyAccounts.tsx` the long list; add-account dialog, the session header's account, the limit notice that continues a conversation under another account). Capabilities (browser control, computer use, remote control) are `SessionOptions` per session, defaults per agent in settings; live state in `SessionMeta.capState` / `remote`. At a limit `server/core/limit-policy.ts` decides: credits (per account, `AppSettings.creditsAtLimit`, only where the agent reports credits or extra usage; the account's own setting with the provider decides whether they are spent), then the next account, then the notice; it also times reset notifications (`limit.reset`) and the return to the preferred account.
- `src/` — UI.
  - `state/store.ts` zustand store (sessions, per-session `data[id]` with `items`, `roots`, `children`, `permissions`, `questions`, `todos`, `caps`). `items` is updated in place (each item stays immutable: a change is a new object) and `rev` changes with every items change; `changedSince(d, rev)` (`state/revision.ts`) gives the ids changed since a selector last looked. Never memoize on or compare `d.items` by identity: use `rev`, `state/actions.ts` (everything the UI can ask the bridge: use these, do not call `bridge.call` from components unless no action exists, then add one), `state/hooks.ts`.
  - `styles/tokens.css` tokens, `styles/base.css`, `styles/ui.css` primitives (classes), `ui/index.tsx` React primitives (Tip, IconButton, Menu*, Popover*, Modal, Switch, Slider, Segmented, Kbd, Toasts), `icons/index.tsx` (`<Icon name>`, `<Glyph>`, `TOOL_ICON`, `MODE_ICON`), `art/` (LogoMark, ProviderMark, Tiles loader, DitherField, and `<Backdrop surface>`: the configured backdrop for home, session, onboarding and the Settings preview; its config is `AppSettings.backdropConfig`, with the default, presets and `normalizeBackdrop` in `shared/backdrop.ts` and uploaded images behind `backdrop.*` in `server/services/backdrop.ts`).
  - `art/events.ts` (`fieldBeat`: the backdrop's one-shot beats) and `art/veil.ts` (the dither dissolve for view changes); see Effects below.
  - `features/<area>/` one folder per area with its own CSS file imported by its component (`onboarding/` first-run welcome, `connect/` sign-in cards, `composer/` incl. `QueueTray`, the thinking control, `Cove.tsx` (the pane's paint) and `Chip.tsx` (a chip whose label changes), `rail/` side panel incl. the Browser tab, `sidebar/`, `usage/` Settings › Usage and `LimitsGlance`/`LimitDot`/`useLimitLevel` for other areas). `app/Capabilities.tsx` the top bar's capability switches. `components/` shared view pieces (Markdown, CodeBlock, DiffView).
  - Conversation (`features/timeline/`): `turns.ts` reduces root items to a shape string and derives turns, segments and each segment's flow (runs of steps, texts, things shown), recomputed only when the shape changes. A turn reads as checkpoints (`TurnView.tsx`): a run of work (steps, thinking, task updates, lead-ins) closed by something in view, usually a note the agent wrote. While the turn runs, each closed checkpoint is two lines (its work folded, "Worked 45s · 5 steps", and its note) and the live line stands under the newest (what it does now, the checkpoint's time and steps; sticky; it steps back while a note or the answer is being written); nothing else of the past shows. When the turn ends everything gathers into one line ("Worked 15m 52s · 36 steps" with the changed files, `changes.ts`) and the answer: the last thing said that is not a lead-in or a nod, with a nod after it ("Committed.") as a quiet last line under it. That line opens the checkpoints one level in, each opening to its own steps; a turn with a single run opens straight to its steps; what was opened is remembered per turn and per run (`fold.ts`). Never folded, in their place after the line: a message steered into the turn with the reply to it right under it (the first text after it, whatever was still running), widgets, files, plans, command output, error notices, and after a failure the last words before it. A lead-in only says what comes next or nods ("Let me run the tests.", "Now the CSS.", "Good.", "Committed.", `lead-in.ts`): it folds with the steps it announces and names the live line; one sentence that says what was found or done makes a text a note. Work the agent begins with no message before it (a wake-up, the turn of a second notification) is a turn of its own with no message at its head, never a row per step. Every piece that folds sits in a wrapper of its own (`.tl-fold`) and keeps its element from the live line to the settled fold, so nothing is made again when a checkpoint closes or the turn ends; a folding piece is `overflow-anchor: none`, so a reader scrolled up keeps the answer in place. `smooth.ts` reveals streamed text at an even pace. A notice that stands as a card says its level by its mark alone (`timeline/notice-read.ts`, `noticeLevel`: informing calm, a warning with the amber mark, an error with the red one): its first sentence, the rest on demand, addresses as links (http and https only), and the same notice right after itself is one card with a count. The navigator (`Navigator.tsx`, pure model in `nav-model.ts`, `navigator.css`; see Added in 0.2.17) is the rail at the conversation's right edge and the index of every prompt it opens.
  - Generative UI (`features/genui/`): `show_widget` items and `widget` / `mermaid` fences render in `WidgetFrame`; `html`/`svg` code blocks get a Preview. Security: the widget runs in a nested frame inside `public/widget-frame.html` (`sandbox="allow-scripts"`, opaque origin, a CSP with no network), and `host.ts` accepts messages only from that exact window, within a budget, with `sendPrompt` allowed only right after a real click in it.
  - `lib/models.ts` how models are named and which ones the model menu lists (`modelName`, `modelNameById`, `visibleModels`): never show an alias name or a raw model id in the UI. By default the menu lists what the agent's own picker offers (`ModelInfo.picker`: Codex's `hidden`/`upgrade`, every model Claude Code reports); the menu asks again when its list is an hour old (`refreshStaleCaps`). Speeds (`ModelInfo.speeds`, `SessionMeta.speed`, `session.setSpeed`, helpers in `shared/speed.ts`) map to Claude Code's fast mode and Codex's service tiers; the composer shows them as on/off rows under the effort ladder, `/fast` toggles the fastest.
- Added in 0.2:
  - Chats and projects: a chat started with "No folder" gets a fresh folder of its own under the chats folder (`server/core/chats.ts`, `AppSettings.chatsFolder`, `SessionMeta.chat`); projects group folders in the sidebar (`group.*`, `project.arrange`, `src/features/sidebar/groups.ts`, `folder-drag.ts`). A usage cap per account (`limit-policy.ts` `capReached`, `pickNextAccount` with `byCap` keeps the person's account order and never moves to an API key).
  - Cross-agent sub-agents: both agents get `delegate_to_codex` / `delegate_to_claude` (`providers/agent-tool.ts`, `core/sub-agent.ts`); the child's steps show under the parent's tool step.
  - Switch agent in place (`session.switchAgent`, `core/agent-switch.ts`, `timeline/AgentSwitch.tsx`): another agent's model in the menu, the palette or `/model <name>` switches the same chat; each agent keeps its own conversation (`SessionMeta.agents`), the next message carries a handover of what it has not seen (`agentHandover`), "Switch back" undoes or returns. Refused while a turn or background work runs. A model change (`session.setModel`, `/model` from anywhere) is never sent: it is applied right before the next message (`applyDue`). The phone shows the switch line and lists the other agent's models in its model sheet.
  - Triage deck (`src/features/triage/`): every permission and question waiting across sessions as one stack of cards, answered by key; `WaitingCount` in the top bar opens it.
  - Before / after (`services/capture*.ts`, `src/features/compare/`): a local page in the Browser tab is captured before and after a turn that edits files; changed regions outlined, compare slider. Offered only where there is a before: a turn whose page was not known or not captured before its first edit takes no picture and shows nothing.
  - Until green (`core/until.ts`, `composer/until.ts`, `UntilStrip.tsx`): `/until <check>` runs the check after each turn and sends the failure back until it passes, within rounds and a usage budget.
  - Lanes (`core/lanes.ts`, `services/git-lanes.ts`, `SessionMeta.lane`, `rail/LaneSection.tsx`, `session/LaneMark.tsx`): a chat that starts in a git folder where another chat works gets a worktree on a branch of its own; the Changes tab forecasts and lands it (`lane.*`). `AppSettings.autoLanes`.
  - Phone (`services/phone.ts`, port 47820, `PHONE_METHODS`; app in `mobile/`, Capacitor, `npm run apk` in `mobile/`): paired by QR from Settings › Phone, token hashed, an allowlist of methods; conversations go to the phone in pages (`PhoneTail`), big fields cut. The phone reads a chat's changes read-only (`phone.changes`, `phone.diff` in `services/phone-changes.ts`: only files the chat folder's git status lists, or the chat's own edits) and sends reviews in the desktop's format. Phone 1.9 adds a Recent list with pins, a deck for what waits, search (`phone.search`), step screenshots (`phone.image`), per-chat notifications and app shortcuts; the phone's boundary checks live in `services/phone-guard.ts`. Phone 2.9 (`versionName` in `mobile/android/app/build.gradle`) reads a turn as checkpoints, as the desktop does (`mobile/src/lib/turns.ts`, `screens/Timeline.tsx`): closed checkpoints and the live line while it runs, one "Worked" line with the change count and the answer once it ends, a steered message and its reply kept as a pair, and a chat whose sub-agents still work says so in the chat and on home. Phone transport (`services/phone-secure.ts`, `mobile/src/lib/secure.ts`): the desktop's P-256 identity (`<home>/phone-identity.pem`) is pinned by a fingerprint in the pairing QR; a signed ECDH handshake bound to the pairing secret, then every frame AES-GCM with a sequence number; files go over that socket in chunks (`phone.fileStart`/`fileChunk`/`fileEnd`, `services/phone-files.ts`; busy answers carry `retry` and `retryAfterMs`, the phone's `whileBusy`), only over the wire whose handshake proved the paired desktop (`conn.sealed()`), checked against the SHA-256 the share recorded (`ToolItem.handed`) before they are published or installed; names are made canonical once (`shared/file-name.ts`, checked again in `FilesPlugin.java`). Phones paired before stay on plain frames until they pair again. Wave 5 and 6 boundaries: a phone approval is limited to what the phone was shown (`core/permission-scope.ts`); every handler gets the guard of the pairing that sent it; long lists come in pages (`phone.sessions`, `phone.prompts` with cursors from `app.hello` and `PhoneTail`), read on by the phone's store, which replays list and prompt events that arrived meanwhile; a message taken back from the queue is kept on the phone first (`mobile/src/lib/take.ts`, `drafts.ts`) and leaves the queue on `phone.takeDone`; Forget moves the pairing's generation on (`mobile/src/lib/epoch.ts`: work begun before writes nothing back) and erases its storage (`erase.ts`, `forget.ts`). Containment of a chat's files (`core/contain.ts`): the handle's own path on Linux, two walks around the open on Windows and macOS (not a proof; its known gap is documented there). Remote Control is on by default per chat; `core/remote-keep.ts` limits how many idle agent processes stay for it.
  - Devices (`services/device.ts`, `providers/device-tool.ts`): `device_*` tools for an Android emulator or phone over adb (screenshot, tap, swipe, type, install, launch, logs).
  - Spare (`core/spare.ts`, `SessionMeta.spare`, `composer/SpareStrip.tsx`): "Continue at reset" on the limit notice, and `/spare <message>` holds a message in the queue until an account has weekly quota projected to expire unused (within caps, never credits, never a reset grant, at most two at once).
  - Long chats: a session file is a base plus a small tail (`core/session-file.ts`; the runtime reports changed items, so a save writes only the tail), and the window gets finished tool steps cut (`core/trim.ts`, cut at the socket in `bridge.ts`, `ToolItem.more`); `session.item` fetches a step whole when it is opened.
  - Turn check (`core/check.ts`, `timeline/Check.tsx`): "Check with Codex" (or Claude Code) under a finished turn with changes; the other agent reviews read-only as a child of the chat, its findings go to the composer.
  - Updates (`services/update.ts`, `update.*`, `UpdateState`): the desktop shell asks GitHub for the newest release, downloads its installer in the background (size and SHA-256 checked) and "Restart to update" (sidebar, Settings › About) runs it silently with `--force-run`; while agents work (a turn, or sub-agents still working in the background) it waits. Dev and standalone bridges report `unsupported`.
  - Bypass and Full access (the modes that never ask, `tone: 'danger'`): in Bypass (`bypassesAsking` in `providers/claude.ts`) Claude Code's own safety prompts are answered at once. Codex fixes a turn's approval policy when the turn starts, so in Full access the asks of a turn begun in another mode are answered at once (`fullAccess`, `allowAtOnce` in `providers/codex.ts`: commands and file changes accepted once, permissions granted for the turn only); a start's answer clears the pending policy only when no mode change came after it was sent. OpenCode's Allow all answers with a one-time grant only (an "always" would outlive the mode inside OpenCode). Switching a chat to a `danger` mode answers the permissions already waiting, never an `ExitPlanMode` plan. Questions (`AskUserQuestion`, Codex's `requestUserInput`) always wait. Each check goes through `SessionRuntime.answersAtOnce`, so a phone's held switch (below) answers nothing early.
  - Review comments (`src/features/review/`, `DiffView` `review` prop): comment on diff lines (Changes tab, applied edit steps); comments gather per chat in a bar above the composer and go as one message (`sendReview`).
  - Race (`core/race.ts`, `src/features/race/`, `SessionMeta.race`, `race.*`): `/race <task>` gives one task to two agents (or two models), each in a lane; the race view shows both side by side; "Keep this one" lands one lane and removes the other.
  - Project scripts (`services/scripts.ts`, `project.scripts`, `rail/scripts-store.ts`, `lib/dev-url.ts`): "Run" in the Terminal tab runs package.json scripts; a local URL a server prints offers "Open" in the Browser tab.
  - Search, export, saved prompts: `services/search.ts` (`search.messages`, shared with `phone.search`: bounded per call, reads chats not open from their files, resumes) feeds the palette's Messages section; `core/chat-markdown.ts` and `services/export.ts` (`session.markdown`, `session.export`) behind the session header's Chat menu; `services/prompts.ts` (`prompts.*`, `<data>/prompts.json`) for saved prompts in the palette, the `/` menu and Settings › Prompts.
  - Chat titles (`core/titles.ts`, `AppSettings.chatTitles`): after a chat's first successful turn its own provider and account name it with their smallest model (Claude: Haiku one-shot; Codex: a throwaway read-only thread); never a title the person set.
  - Previews (`services/thumbs.ts`, `electron/thumbs.ts`, `file.thumb`, `phone.thumb`): file cards show the real picture, PDF page or video frame (Electron's shell thumbnails passed in like the updater's host, Windows' PDF renderer as a fallback); the phone gets only the exact shared file (`ToolItem.handed`, `core/handed.ts`).
  - Start-up (`src/boot.ts`, `src/lib/boot.ts`, `server/util/boot.ts`): a tiny boot script opens the bridge and asks `app.hello` while the bundle loads and starts the launch light; the launch releases once home is there; the Agent SDK loads from `dist-electron/sdk.cjs` on first Claude use; `SABLE_BOOT_TRACE=1` prints the stages.
  - Keep awake (`core/awake.ts`, `keepAwake` in `electron/main.ts`): while a turn, an /until check or background work (`SessionMeta.background`) runs anywhere, Windows does not suspend; released a minute after.
  - Profile (`services/profile.ts`, `providers/profile-tool.ts`): `<home>/profile.md`, the person's own text plus facts agents saved with `remember_about_user`; read into every session.
- Added in 0.2.17:
  - Use first (`shared/use-first.ts`; what a window is, read from its id, in `shared/limit-windows.ts`): an agent's accounts in the order that lets the least quota expire unused. First those that take work now, the soonest end of the week first (weeks that end within the same quarter hour: the one with more left for its plan size); then those held by a full window (the 5-hour one at 97% or the account's session cap, or the chat model's own week), soonest free first; then the spent ones (under 5 points left within the cap), soonest back first; then the unread and the off (signed out, API keys). Pure, one rule for the bridge and the desktop. `AppSettings.accountsBy` (`useFirst`, absent means this; `manual`: the saved `accountOrder`; a switch in Settings › Accounts) decides both how every list shows an agent's accounts (`useAccountOrder` in `src/features/accounts/order.ts`, for the switcher's short list, which shows each week's end as "27h" or "3d", and `ManyAccounts`) and where a chat moves at a limit (`pickNextAccount` in `server/accounts/folders.ts` through `App.nextAccount`: only an account that takes work now, else one whose week was never read and whose 5-hour window has room; never an API key; only the windows of the chat's effective model count, and an account whose known models leave out the chat's own is not taken). A move by a cap always keeps the person's order (`byCap`).
  - Background work (`SessionMeta.background`, `worksInBackground` in `shared/background.ts`, counted by `SessionRuntime` from its steps): sub-agents and workflows still working after the chat's own turn ended. One rule for the count and the Agents tab: a step in a terminal state never works on, a workflow's own status outranks its launch result; work whose process is gone (it ended, Sable restarted) is marked stopped (`stopBackground`). Above 0 the chat is not at rest: keep awake and updates wait for it, an account move and an agent switch are refused, the sidebar, the palette and the quick switcher show the working mark ("2 sub-agents working", `statusTone`/`statusLabel` in `sidebar/SessionRow.tsx`), `timeline/Tail.tsx` shows one line that opens the Agents tab, and the phone says it in the chat and on home.
  - A message goes out once (`src/features/composer/pending.ts`, `restore.ts`, `server/core/submissions.ts`, `src/lib/bridge.ts`): words and attachments leave the field only once the bridge accepted them. A send is kept beside its draft until then (written with the drafts, so a reload brings it back; a first send from home moves to its chat once the chat exists) and goes back into the field when it is refused, in the order sent. Every send carries a submission id (`session.send` `submitId`): the bridge remembers each message under it for a few minutes (by its words and files, not by whether it steers) and answers a repeat without sending twice; a phone's send never carries one. A request that waited for the socket is dropped the moment it fails. Not covered: the id is not kept across a reload, and `/race` and race follow-ups have none.
  - A steered message is answered first: a message sent into a running turn goes with `STEER_FIRST_BLOCK` (`shared/protocol.ts`, a `<system-reminder>` after the person's words) telling the agent to answer it in a sentence or two before any further tool call, then carry on. Claude Code gets it as a text block of its own beside the message (not for a slash command); Codex in the `turn/steer` input, and `codex-map.ts` drops it when a thread is read back; `shared/synthetic.ts` hides it wherever a transcript is read, so the conversation shows only what the person wrote. OpenCode takes no message mid-turn (it waits in the queue). The turn view keeps the message and the reply under it as a pair (Conversation, above). A steered message waits where it was sent and, once the agent takes it, stands where the agent took it (`SessionRuntime.taken`): whatever the agent wrote after it was sent and before it had it stays above the message, so the first words under it are the reply to it; it keeps the time it was sent.
  - Navigator (`timeline/Navigator.tsx`, `nav-model.ts` pure, `nav-bus.ts`, `navigator.css`): at the conversation's right edge once it is two views tall. Messages the person sent close together form a run; a closed run is one short stack, the run being read fans out into a line per message with the one in view lit, so 300 messages are about a dozen marks; amber marks a prompt waiting on the person, red a failed turn. Resting on the rail or Ctrl+G opens the index beside it: every message by its first words under the time its run began, the one in view marked, typing filters, Enter or a click jumps. Alt+Up and Alt+Down step message by message (the find bar hands the keys over). It never makes the timeline render: the turn list hands it its layout after each commit, it measures built turns only when the layout or a size changes, and the lit mark moves by one transform; nothing runs per streamed word. In a race each conversation has its own.
  - Customize Sable (`server/services/custom.ts`, `src/features/customize/`, Settings › Customize, the palette's "Customize Sable", `/customize <what you want>`): the person's own styles, `<data>/custom/styles.css`, plain CSS over the app's classes and tokens, served at `/custom/styles.css` to the app's own origin only, linked after the app's styles (`src/boot.ts`) and swapped in place on every save (`custom.updated`, `customize/live.ts`); it survives updates. ## Design language (read this twice)

The brief from the owner: far better looking than Claude Code's own app; modern, simple, clean; dark, calm panels over a rich backdrop; subtle background effects; colourful dither; rich detailed icons; beautiful motion; cinematic. He rejected the earlier tactile look (lit edges, gradient fills, bevels) as cheap: controls are quiet, flat and precise, premium through proportion, spacing and type. Explicitly forbidden: monospace uppercase labels, "eyebrow" kickers above headings, sloppy colours, generic AI-app look.

Newer guidance from the owner: really clean and professional. No descriptions in pickers and menus (expect people to know), no helper sentence that restates a label, no decorative colour on controls, no tags or badges that do not carry needed information, nothing extra on the home screen.

Latest guidance from the owner (21 Nov 2026): he lived with the liquid glass and tactile look of 20 Nov for two days and rejected it as built: a top edge brighter and thicker than the sides and bottom, bright corners, a sheen fading down from the top, a pane that goes light when clicked, bevels on controls. What floats stays glass, but calm, even and precise: one hairline rim that reads the same all the way round, a clean frosted fill, depth from the shadow alone. Controls are flat again: no skeuomorphism. He judges by details: a bright edge or a one-frame flash reads as cheap. Colour still only in the field and the agent marks.

- Monochrome: ink surfaces, ivory text. Surfaces are neutral near-black: `--shell` is the window's body (the sidebar's rows sit right on it, and it frames the sheets), `--sheet` the stage and the side panel, wells of the deepest ink set into it where the field glows; `--panel`/`-2`/`-3` are each one step above a sheet, `--bg` the launch's ink; `--fill-*` for hover/selected, `--hl` for a highlighted row, hairlines `--line*`. The sidebar reads `--text-4-shell` for its dimmest words. Colour lives only in the backdrop (the dither field) and the agent marks, plus tiny meaningful marks: `--amber` waiting on you, `--red` error, green/red numbers in diffs. `--accent` is neutral ivory. No tinted icons or tiles, no coloured chips or buttons, never a hue as decoration, never new colours: use tokens.
- Depth: ink and light. In-flow surfaces (cards, panels, the timeline, plain buttons, fields) are flat; depth comes from layering (each layer one small step lighter) and from light that reacts. The window has one order: the body, one clear step lighter, and the sheets cut into it. Wherever the panel moves apart from the stage, the stage's round end is drawn on every frame (`app.css`, `.app-rail:not([data-open])`), and a veil over the panel stays on its sheet. There is one light, from the top and slightly left; every highlight and shadow below agrees with it. Reactive hairlines: borders are almost invisible at rest and brighten near the pointer on any element with `data-spot` (cards, panels, menus, dialogs, the composer; `ui/spot.ts` runs the one listener and appends a `.spot-ring` span, so never write your own pointer listeners). Small accents use monochrome dither, never gradients: `.dither-sel` on a selected row's pill, `.meter` + `.meter-fill` (`--p`, `data-level`) for progress, `.skel` for skeletons. Controls: `.btn` is one fill step with an almost invisible hairline, hover one step lighter, press `scale: .97`; one solid ivory `.btn-primary` per view; fields are a darker well whose hairline turns soft ivory on focus (`--focus-field`); the focus ring is ivory at reduced strength (`--focus`).
- Glass (the material of what floats; tokens `--rim-*`, `--glass-*`, `--shadow-glass*` in `styles/tokens.css`, rules under "material: glass" in `styles/ui.css`, every state in the gallery's Material section). Where: the composer (home and dock), menus and popovers (`.pop`), dialogs (Settings, History, the folder picker, Add account, Before / after), the command palette, the quick switcher, the account switcher's limits beside its menu, the triage deck's cards and its end line, `.glass` (find bar, "Jump to latest"), toasts; another floating layer may wear `.glass-liquid` (an opaque pane with all of it) or `.glass-rim` (the rim alone, for a layer that keeps its own fill and sets `box-shadow: var(--rim-inner), var(--shadow-glass)` itself). Tooltips are opaque, with the same hairline and depth in one box-shadow (`--shadow-tip`). The person's message is no glass: a dark well (`rgb(0 0 0 / 0.34)`, one even hairline, nothing lifted; `.user-card::before`; its numbers repeat for the flying copy in `composer.css` `.send-surface` and `liquid-shape.ts` `INK`: change them together). Nothing else in flow, nothing that scrolls: a menu whose rows scroll puts the scroller inside the `.pop`, and hover bars inside the conversation stay flat (`--shadow-pop`). All static paint: (1) the fill: frosted ink in one even tone with the static grain (`--grain`) and a backdrop blur (`--blur`; opaque for dialogs and toasts, which never blur); (2) the rim, the surface's `::before` (so `::before` is taken): a 1px masked ring filled with `--rim-light`, the same strength on all four sides and round every corner; (3) `--rim-inner`: a faint glow just inside the rim, the same all round; (4) depth, `--shadow-glass`: a dark contact line, a near shadow and a wide soft one. Never a glint, a brighter top edge, a bright corner, a sheen or band fading down from the top, thinner edges, or a fade laid over glass (on a translucent pane it shows as a pale band). The reactive hairline on glass is the rim itself, a little brighter near the pointer (`--spot-glass`, weak and wide), never a second line; on the composer, wide and low, the whole rim steps up evenly with a touch more near the pointer. The composer (`composer.css`, `composer/Cove.tsx`) is the main pane, "the cove": one pane of `--glass-pane`, thin enough for the field's colour, whose bottom-right corner is carved by a concave arc; in that cove rests the send key, a disc of the pane's own corner radius that is no part of the pane, a 6px channel between them, the same all the way round. The card stays a plain rectangle that everything measures and lays out in and paints nothing itself; its paint is static layers: the glass cut to the outline (`clip-path: shape()`, lengths from the bottom-right corner, so it follows any size without script), the rim (the straight edges and the three plain corners a masked ring on whole pixels as on every pane, the cove's curve a 1px band between two shapes), and the shade under it (a clip cuts a box-shadow away, so the contact line, the near shadow and what falls into the channel are layers of their own, with the numbers of `--shadow-pane`: a contact line, a short near shadow and one soft shadow under the pane, far less than a menu casts, since the pane lies on the field). The outline's numbers sit between `cove:begin` and `cove:end` in `composer.css`, derived from the key, the channel and where the straight edges end; `tests/cove.test.ts` derives them again. On focus it draws no ring, never goes lighter and never darkens what is round it: two layers only fade in by opacity, both inside the outline (a little more ink, `--glass-pane-lift`; the hairline a step clearer all round, the cove included) and the placeholder steps back. The pane is held the same way while focus is anywhere in the composer or one of its menus is open. Effort is a scale on the bar (`composer/Thinking.tsx`, `effort-track.ts`): its pips and its name, dragged sideways or stepped with left and right, ultracode the stop past the end; a click opens the ladder, with the speeds as on/off rows under it. The bar shows complete in a chat's first frame: the agent's last known models and effort are kept (`composer/caps-seen.ts`). Long text is cut at the field's edges. The pointer's ring is the composer's own (a `.spot-ring` of `.spot-part`s that `ui/spot.ts` moves together), so it follows the cove. The strips that belong to the composer (until, spare, review, the queue tray) are one stack tucked behind its top edge with its corners and its hairline (`until.css`). A narrow pane sheds in order, and the cove and key never change: the effort's name goes and its pips stay, the model's name shortens, the mode keeps its icon. Rows, text and controls on glass stay flat. Rules: monochrome; never animate the rim or a shadow (fade a layer's opacity instead); when the governor sheds effects (`data-quality`) glass loses its blur and goes opaque (the composer: `--glass-pane-solid`).
- Flat controls (tokens `--press-*`, `--key-*`, `--thumb-up`, rules under "material: flat controls" in `ui.css`). The few controls with a fill of their own (the composer's attach disc and mode chip, a segmented control's pill, the selected row's pill, `.srow-pill` and `.dither-sel`, wherever a list has a selected row) are one fill step and one even hairline (`--press-up`). Hover is the next fill step, held one more with the small give in scale; open or on holds the hover step and the hairline steps up (`--press-down`). A bare chip (model, effort, the plain `.chip`) has no edge until it is held, open or on. A chip whose label changes (`composer/Chip.tsx`: mode, model, effort, ultracode's mark, the home chips) is one motion of about 140 ms on the compositor: the layout takes the new width at once, the chip's skin glides to it (two windows on one long pill, the far one sliding, so nothing is scaled and no width is ever animated), what stands beside it rides along, a part that stays keeps showing, the old word is gone before the new one comes in behind the moving edge; no word is ever outside its chip. Tracks (a switch, a segmented control) are a darker fill with the same hairline (`--press-well`); thumbs are flat discs with a short drop (`--thumb-up`). The send key is the one ivory key: a 40px disc in the composer's cove, a flat ivory face and a short soft drop (`--key-up`); hover goes to white, held it sinks (its give in scale: the channel round it widens), dims a touch and the drop shortens (`--key-down`) in the same frame; with nothing to send it is a disc of the pane's own glass with the pane's rim and a dim arrow; the stop key is the same key with a dark square and never moves; the compare slider's handle is the same key. Hairlines and drops swap in one frame with the state; nothing transitions them. Never a top light, an inner shade, a lip, a gradient face or a gloss: states read by fill and the give in scale (a menu's highlighted row is light, not a press). `.tactile` is only the old class name of a filled control.
- Type: Inter (variable, optical sizes; `--font-sans`) for the interface; Geist Mono (`--font-mono`) only for code, diffs, terminal output and inline code. Paths, folder names and commands shown as labels use the UI font with the directory dim and the name regular (`<PathLabel path>`, `.path`), never mono. A path too long for its place is cut from its start; in menus, settings and dialogs pass `fit` (`ui/path-fit.ts`): it is then cut by whole folders ("…/Local/Temp/", starting on the label's own left edge, the name right after), measured in layout pixels and fitted again when the window changes size; rows that mount by the hundred (a turn's steps) keep the plain cut. 13px UI, sentence case everywhere, no uppercase or letter-spaced labels. Use the scale (`--t-*`) and weights (`--w-*`: 400/500/580); headings are 600 and tight (`.h1/.h2/.h3/.display`); figures that line up use `.num` (tabular). Small secondary text is `--text-2`/`--text-3`, never below 11.5px.
- Shape: radii from tokens (`--r-sm` 8 controls, `--r-md` 10, `--r-lg` 12 cards/menus, `--r-xl` 14 panels, 16 menus (what nests in a pane takes the pane's radius less its distance to the edge: menu rows and the highlight are 12 in a 16 pane with 4px padding), 20 the composer and its send key: a disc of 20 in the pane's cove, which is a circle of 26 about it; the cove's horns are the pane's own corner, what stands 6 in from the pane's edge is 14, attachments 10, and the bar's menus stand 8 clear of the pane, flush with its side, their side decided before they are drawn, `composer/menu-place.ts`). Controls are 30px tall with 13px text (`--t-ui`), the chips and the attach button on the composer's last line 28px and fully round, 6px from the pane's edges and on the key's centre line, menu rows 26 to 28px. Calm rhythm, a single column (`--column`) for reading.
- Icons: plain line icons, monochrome. `<Icon name>` (Phosphor regular; bold for tiny carets and checks) inline; `<Glyph name>` is the same plain icon in a fixed box for rows that need alignment (its `tone` only applies when it is amber or red). Icons answer the control they sit in (`icons/animated/play.ts`: one set of document listeners marks the icon's svg, features never listen themselves): pointed at or focused, each plays its motion once (`data-ai`), 520 to 860 ms with a beginning, a middle and a settle; pressed, a 280 ms beat of its own (`data-ap`); an icon that changes under a pressed control (copy to a check and back) arrives (`data-ai-in`). A row of a menu or picker plays its leading icon once the pointer rests on it, and so does a control marked `data-ai-rest` (the sidebar's project headers); rows of dense lists (`-row`, the conversation's steps, the sidebar's chats) and `data-still` stay still; `data-ai-scope="<selector>"` on a control widens what answers it (a file card's cover), `data-ai-host` makes any element a control, `playIcons(el)` plays from code. Never emoji. Add missing icons to `icons/index.tsx` using the per-icon Phosphor import pattern there.
- Motion: purposeful, fast, soft. Enter with a short rise + fade (never a blur filter), spring for things that move (`motion/react`, stiffness 380–520, damping 32–40), `--ease-out` for CSS. Durations from tokens (`--d-1..4`). Animate height when revealing details. Nothing bounces wildly, nothing loops except the working indicator (`<Tiles>`), `.shimmer` text and the dither field. Respect `prefers-reduced-motion`. Menus and popovers (`ui/grow.ts`, `ui/glide.ts`, "the feel of the primitives" in `ui.css`): a pane unfolds out of its trigger in 130 ms on `--ease-unfold` (a third of the way in its first frame, never a two-frame pop; a context menu from the pointer), its shadow a layer behind it scaled from the same origin so it hugs the pane at every frame, and the rows arrive just behind it, nearest the trigger first (11 ms apart, 5 px, all in one span so the pane is painted once before and once after). One highlight glides between rows for keys and pointer alike (110 ms; the row's words light in the same frame); its place is its row's place in the layout (`layoutBox` in `ui/glide.ts`), never a drawn rectangle, since rows arrive 5 px short of their place: under a row still arriving it fades in on that row's clock, and a menu that opens on a row makes it its first focus, so the highlight lands once; a pick steps it up one fill, holds 40 ms (`data-picked`, `--d-pick`), then the menu folds back in 95 ms. A tooltip arrives 3 px from its control and the next one along a toolbar is simply there. Dialogs come forward in 170 ms on the same curve and leave in 95. List rows under the pointer light and let go in the frame; the tools at a row's end wait 50 ms for the pointer to rest and swap with what they replace in one frame; only leaving the list fades. Press gives in 70 ms and releases on `--spring-soft` (260 ms, a hair past) everywhere; a switch's thumb travels on the same spring, stretched while held. `Collapse` starts in the frame of the click, the content fading in 30 ms behind the height. A toast never takes focus. The sidebar's toggle runs on one clock: the column's width, the top bar's slot for the mark (`.topbar-home`, always in the bar, closed while the sidebar shows) and the centring of the stage's view, which keeps one width meanwhile (`data-freeze='side'`, `useStageFreeze` in `sidebar/Sidebar.tsx`), are laid out on the same frames, so the toggle, the title, the conversation and the composer travel as one; only the mark's own copy flies on the compositor (`sidebar/brand-flight.ts`). Never slide a part of it with an animation of its own: that keeps its own time and runs ahead of the stage's edge whenever the page is busy.
- Effects: the spectacle lives in the backdrop and at a few moments, never on controls. The field answers the app with one-shot beats (`fieldBeat(kind, el)` in `art/events.ts`, drawn in the worker, `FieldBeat` in `art/field.ts`): `send` (a pressure wave from the send key: thin crest that bends the pattern, a trough, an echo), `done` (a ring closes in on the composer as the turn's steps gather, then the band exhales), `fail` (the light dips and recovers), `pulse` (a softer wave for small moments). While a turn runs the field drifts quicker; waiting on you it stills (amber band). Strength follows the surface (full on home, restrained in a session, nothing when the backdrop is off, still or under reduced motion) and the backdrop's own amount, speed and reaction settings; no new switches. The pointer leaves a faint light that trails it on full stages. Rest: after 20 s with no input and no running turn the field eases to a still frame and stops drawing (no timer, no frame) until input or a beat wakes it. View changes use the dither veil (`veil(host, 'swap' | 'reveal' | 'cover')` in `art/veil.ts`): four quarter-tiles of the 4x4 ordered dither in the surface colour, stepped by opacity only, so content dissolves into the ground and resolves out of it (sparse, checker, solid, as the mark builds) on the compositor; 260 ms for a swap, the views only change opacity and transform, nothing reflows. The launch (`art/LaunchLayer.tsx`, light drawn in the worker by `art/launch-light.ts`): one cell ignites, a wake of dither thresholds builds the mark from its own cells, it holds while the bridge starts, then a crest opens the ink in dither order onto home while the mark glides to its place; a key or click yields at once and nothing is left running. The home mark glints a missing corner cell per keystroke. A send is one drop of liquid glass that leaves from the send key (`composer/flight.ts`, the path and springs in `liquid-shape.ts`, drawn in a worker with WebGL in `liquid-gl.ts`, 2D fallback; the key's own part in `launch.ts`): the key gives in its cove and its arrow leaves up through its top, the words run as one piece down into the pane's corner over the key while the field closes to one line, the pane rests empty for a moment, a drop rises from behind the key's top on a thin thread that parts and snaps up into the drop as the key comes back up (the stop square grows where the arrow was), the drop coasts straight up to where the row lands, stretched along its speed, with a small highlight from the top left and the field refracted behind it (its only colour), lands still moving and wets out into the card, revealing the words in place (readable about 400 ms after the key), and the real row takes over. One path and one speed that never steps, and one clock: time zero is one frame before the first frame the words show in, so that frame already moves; the worker's drawing, the page's layers and the key's part all run on it (the layers that show later are put on it explicitly: left on the compositor's own start, the card's surface could form after the sheet under it had let go, and the card blinked before the row took over); the key handler reads the page once and then only writes. The field's `send` wave starts where the thread parts and a softer ripple where the drop lands (`fieldBeatAt`). From home the composer leaves for the dock (`home/handoff.ts`) while the thread still holds; the queue gets the same drop as a hop into the tray row; steer and send now the same motion. Nothing is left behind at rest; under load the worker sheds the refraction and the soft shadow before frames; reduced motion is a calm fade. A steer leans in sideways, cools to the waiting tone, and a hairline wire ties it to the turn; when taken, a light runs along it; a taken steer that moves to where the agent took it glides there and plays no second entrance (`timeline/user-card.ts`), and a card whose row is late keeps its tone and shows only a hairline. Streamed text is written at a zero-width write head (`.md-caret` in `components/Markdown.tsx`) whose short feather lifts off the newest words. Icons move with their control (`icons/animated/`: Phosphor redrawn as parts in `parts.tsx`, the motion in `animated.css`, when it plays in `play.ts`): each icon does what it means, once, in 520 to 860 ms: an anticipation that already answers in the first tenth, the act, a hold, a settle a hair past (`--ai-spring`), starting and ending on the rest pose, never a plain spin, never blank. Leaving early never drops it: barely begun it runs back, further along it runs out, both quicker. The press beat (280 ms: a pinch, a jab the way it points, a turn that ends on the same picture, a lid that claps) animates the individual `translate`/`rotate`/`scale` while the hover motion animates `transform`, so it plays over a hover still under way; each part's `animation` is put together from one never-inherited custom property per layer (`--ai-h`, `--ai-p`, `--ai-n`), and a motion's keyframes carry its layer's prefix (`ai-`, `ap-`, `an-`), which is how the engine knows them. Icons without a drawn version take one small step in their direction and spring home. File cards (`timeline/FileCard.tsx`, `files.css`): a share that happens on screen while you watch arrives (the sheet rises into the well and settles, its corner turns down, lines, rows or the cover's drawing draw in, a picture develops; cards a beat apart), a card pointed at lifts its sheet a hair with the fold answering and its cover gives its kind's one motion (a document, a table, a picture, an archive, a video, sound, code; `coverKind` in `file-sheet.ts`), opening gives the sheet a beat; history stands still, and an arrival rule only ever adds to an element's animations, so taking its mark away starts nothing. Every icon and every cover is in the gallery's first section (`?gallery`; `&strip` scrubbed frames, `&live` rest copies only, for films). Rules: every effect is one-shot and a few hundred ms (the field, `<Tiles>` and `.shimmer` are the only loops); colour only in the field and the agent marks; transform, opacity and worker canvas only (no `filter`, no animated `box-shadow`, no `mask-image` on live content); zero cost at rest; under load the governor sheds the effects (bending, echo, pointer light) before it lowers the frame rate. A moment that is not clearly better than nothing is removed.
- Density: quiet by default, detail on demand. Rows are one line until expanded. Secondary actions appear on hover/focus. Empty states are one calm sentence, no illustrations.
- Copy: plain, specific, short. Say what happens ("Allow once", "Rewind to here"), no exclamation marks, no filler, no em dashes, no marketing voice.
- Every interactive element needs hover, active and focus-visible states, an accessible name, and keyboard access. Show shortcuts with `<Kbd combo="mod+k">`.
- Performance is part of the design: streaming must never re-render settled items; subscribe narrowly to the store (`useStore(s => s.data[id]?.items[itemId])`), memoize, avoid layout thrash, keep animations on transform/opacity. `backdrop-filter` only on small floating layers and the composer; no `mask-image` on scrollers or animated content (use a gradient overlay pseudo-element in the surface colour; the static 1px rings of glass and of `data-spot` are the exception); no `filter` in animations or at rest; hover/press transitions on background-color, color, opacity or transform only, 80 to 120ms, never on box-shadow, border or size; menus open in about 120ms; `will-change` only while something animates.
