# Sable

A desktop ADE (agentic development environment) for Claude Code and Codex. Vite + React 19 + TypeScript, shipped as an Electron app for Windows (`electron/main.ts`, page-drawn window controls in `src/app/WindowControls.tsx`). One process serves the UI and hosts the bridge.

## Commands

- `pnpm dev` starts Vite with the bridge attached (WebSocket at `/__sable`). It runs on the real profile (`~/.sable`): every Demo session a test starts there lands in the owner's sidebar. For tests and screenshots start `node scripts/dev-test.mjs` instead (same server on a throwaway data folder, `%TEMP%/sable-dev-home`). A dev server is usually already running on http://localhost:5173 (or 5174 when that port was taken) — reuse it, never start a second one. `scripts/shot.mjs` finds it by itself.
- `pnpm exec tsc --noEmit -p tsconfig.json` type-checks everything. `pnpm exec vitest run` runs tests.
- Smoke scripts: `pnpm exec tsx scripts/claude-smoke.ts`, `scripts/codex-smoke.ts`. Real agent turns (these scripts, or any session with Claude or Codex) cost the owner's quota and need his say-so each time.
- `http://localhost:5173/?gallery` (dev only, `src/dev/Gallery.tsx`) shows every control primitive in every state.
- Performance: `node scripts/perf-headless.mjs [--label x] [--only a,b]` measures work per interaction against the dev server, headless (results in `scratch/speed/`); `node scripts/perf-electron-idle.mjs` reads the idle CPU of the built desktop app, off-screen (needs `pnpm desktop:build`). Never run `scripts/perf-electron.mjs` while someone uses the machine: it opens a visible window.
- Widget checks, headless: `scripts/widget-sandbox-check.mjs` (what a hostile widget can reach), `scripts/widget-stream-check.mjs` (a widget streaming in).
- Desktop builds: `pnpm desktop:pack` (unpacked, `release/`), `pnpm desktop:dist` (installer). For checks, build into another folder (`pnpm desktop:build && pnpm exec electron-builder --dir --config.directories.output=release-qa`); never touch `release-sable/`, the owner runs his copy from there.
- Driving the packaged app off-screen: start `Sable.exe --screenshot=<file> --wait=3600000 --eval=1 --remote-debugging-port=<port>` with `SABLE_HOME` and `SABLE_USER_DATA` pointed at new temporary folders and `SABLE_DEMO=1`. `--screenshot` keeps the window at -32000,-32000 and out of the taskbar; `--eval` enables the `sable` helpers; connect with playwright-core's `chromium.connectOverCDP` (add `--inspect=<port>` to reach the main process). Local recipes (git-ignored): `scratch/desktop/lib.mjs`, and `scratch/docs/lib.mjs` for shots at 1440x900 and 2x with an empty home. Never show, focus or maximise the window. For anything that may be seen, also point `USERPROFILE`, `CLAUDE_CONFIG_DIR` and `CODEX_HOME` at empty folders, or the real agents show the owner's accounts and usage. Kill what you start and delete the folders.

## Architecture

- `shared/protocol.ts` is the contract. The bridge owns all state; the UI is a view that calls RPC methods and applies events. Every provider is normalized into one timeline model (`TimelineItem`: user, text, thinking, tool, notice, turn). The UI never branches on provider id except for marks and colour.
- `server/` — bridge. `app.ts` (RPC handlers, sessions, accounts, prewarm), `core/runtime.ts` (SessionRuntime: timeline + prompts + the queue of messages sent mid-turn), `core/cache.ts` (DiskCache: last known sign-in and caps under `~/.sable/cache/`, served at start-up, refreshed in the background), `providers/` (`claude.ts` via the Agent SDK, `codex.ts` via `codex app-server`, `demo.ts` scripted; `widget-tool.ts` the `show_widget` tool both agents get; `browser-tool.ts` the Browser tab tools both agents get, `browser_read`, `browser_screenshot` and `browser_open` answered by the window that shows the session's Browser tab, off per session with `SessionOptions.browserTab`), `services/` (fs, git, terminal, memory, config, backdrop; `usage.ts` a read-only incremental scanner of the agents' transcripts for tokens by day, model, project and session; `limits.ts` plan limits per account with a short history per window, for pace), `accounts/` (`folders.ts` finds existing config folders by their listing only, `handover.ts` carries one conversation's transcript to another account).
- Accounts: each agent has the built-in default account plus extras (`AccountInfo`, own config dir under `~/.sable/accounts/`, or an existing folder used in place); sessions carry `accountId`, caps are keyed by provider + folder + account (`capsKey`). Sable never opens a file that holds a sign-in: auth and limits are asked of the CLIs (Claude's limits come from the SDK's usage request and each turn's `rate_limit_event`). UI in `src/features/accounts/` (sidebar switcher with each account's limits, add-account dialog, the session header's account, the limit notice that continues a conversation under another account). Capabilities (browser control, computer use, remote control) are `SessionOptions` per session, defaults per agent in settings; live state in `SessionMeta.capState` / `remote`. At a limit `server/core/limit-policy.ts` decides: credits (per account, `AppSettings.creditsAtLimit`, only where the agent reports credits or extra usage; the account's own setting with the provider decides whether they are spent), then the next account, then the notice; it also times reset notifications (`limit.reset`) and the return to the preferred account.
- `src/` — UI.
  - `state/store.ts` zustand store (sessions, per-session `data[id]` with `items`, `roots`, `children`, `permissions`, `questions`, `todos`, `caps`). `items` is updated in place (each item stays immutable: a change is a new object) and `rev` changes with every items change; `changedSince(d, rev)` (`state/revision.ts`) gives the ids changed since a selector last looked. Never memoize on or compare `d.items` by identity: use `rev`, `state/actions.ts` (everything the UI can ask the bridge: use these, do not call `bridge.call` from components unless no action exists, then add one), `state/hooks.ts`.
  - `styles/tokens.css` tokens, `styles/base.css`, `styles/ui.css` primitives (classes), `ui/index.tsx` React primitives (Tip, IconButton, Menu*, Popover*, Modal, Switch, Slider, Segmented, Kbd, Toasts), `icons/index.tsx` (`<Icon name>`, `<Glyph>`, `TOOL_ICON`, `MODE_ICON`), `art/` (LogoMark, ProviderMark, Tiles loader, DitherField, and `<Backdrop surface>`: the configured backdrop for home, session, onboarding and the Settings preview; its config is `AppSettings.backdropConfig`, with the default, presets and `normalizeBackdrop` in `shared/backdrop.ts` and uploaded images behind `backdrop.*` in `server/services/backdrop.ts`).
  - `art/events.ts` (`fieldBeat`: the backdrop's one-shot beats) and `art/veil.ts` (the dither dissolve for view changes); see Effects below.
  - `features/<area>/` one folder per area with its own CSS file imported by its component (`onboarding/` first-run welcome, `connect/` sign-in cards, `composer/` incl. `QueueTray` and the thinking control, `rail/` side panel incl. the Browser tab, `sidebar/`, `usage/` Settings › Usage and `LimitsGlance`/`LimitDot`/`useLimitLevel` for other areas). `app/Capabilities.tsx` the top bar's capability switches. `components/` shared view pieces (Markdown, CodeBlock, DiffView).
  - Conversation (`features/timeline/`): `turns.ts` reduces root items to a shape string and derives turns, segments and each segment's flow (texts, widgets and plans, runs of steps, the work line), recomputed only when the shape changes. The agent's texts are always in view in order, all at full strength (only thinking sits back), except one-line lead-ins ("Let me run the tests.", `lead-in.ts`), which fold with the steps they announce and name the live line while those run; the steps fold behind one line that opens them all in their places: while running it is the live line (what it does now, the time, N steps; sticky), settled the summary with its changed files (`Turn.tsx`, `changes.ts`). `smooth.ts` reveals streamed text at an even pace; `fold.ts` remembers what the reader opened.
  - Generative UI (`features/genui/`): `show_widget` items and `widget` / `mermaid` fences render in `WidgetFrame`; `html`/`svg` code blocks get a Preview. Security: the widget runs in a nested frame inside `public/widget-frame.html` (`sandbox="allow-scripts"`, opaque origin, a CSP with no network), and `host.ts` accepts messages only from that exact window, within a budget, with `sendPrompt` allowed only right after a real click in it.
  - `lib/models.ts` how models are named and which ones the model menu lists (`modelName`, `modelNameById`, `visibleModels`): never show an alias name or a raw model id in the UI. By default the menu lists what the agent's own picker offers (`ModelInfo.picker`: Codex's `hidden`/`upgrade`, every model Claude Code reports); the menu asks again when its list is an hour old (`refreshStaleCaps`). Speeds (`ModelInfo.speeds`, `SessionMeta.speed`, `session.setSpeed`, helpers in `shared/speed.ts`) map to Claude Code's fast mode and Codex's service tiers; the composer shows them as the Speed row of the thinking popover, `/fast` toggles the fastest.
- Added in 0.2:
  - Chats and projects: a chat started with "No folder" gets a fresh folder of its own under the chats folder (`server/core/chats.ts`, `AppSettings.chatsFolder`, `SessionMeta.chat`); projects group folders in the sidebar (`group.*`, `project.arrange`, `src/features/sidebar/groups.ts`, `folder-drag.ts`). A usage cap per account (`limit-policy.ts` `capReached`, `pickNextAccount` with `byCap` keeps the person's account order and never moves to an API key).
  - Cross-agent sub-agents: both agents get `delegate_to_codex` / `delegate_to_claude` (`providers/agent-tool.ts`, `core/sub-agent.ts`); the child's steps show under the parent's tool step.
  - Switch agent in place (`session.switchAgent`, `core/agent-switch.ts`, `timeline/AgentSwitch.tsx`): another agent's model in the menu, the palette or `/model <name>` switches the same chat; each agent keeps its own conversation (`SessionMeta.agents`), the next message carries a handover of what it has not seen (`agentHandover`), "Switch back" undoes or returns. Refused while a turn or background work runs. A model change (`session.setModel`, `/model` from anywhere) is never sent: it is applied right before the next message (`applyDue`). The phone shows the switch line and lists the other agent's models in its model sheet.
  - Triage deck (`src/features/triage/`): every permission and question waiting across sessions as one stack of cards, answered by key; `WaitingCount` in the top bar opens it.
  - Before / after (`services/capture*.ts`, `src/features/compare/`): a local page in the Browser tab is captured before and after a turn that edits files; changed regions outlined, compare slider.
  - Until green (`core/until.ts`, `composer/until.ts`, `UntilStrip.tsx`): `/until <check>` runs the check after each turn and sends the failure back until it passes, within rounds and a usage budget.
  - Lanes (`core/lanes.ts`, `services/git-lanes.ts`, `SessionMeta.lane`, `rail/LaneSection.tsx`, `session/LaneMark.tsx`): a chat that starts in a git folder where another chat works gets a worktree on a branch of its own; the Changes tab forecasts and lands it (`lane.*`). `AppSettings.autoLanes`.
  - Phone (`services/phone.ts`, port 47820, `PHONE_METHODS`; app in `mobile/`, Capacitor, `npm run apk` in `mobile/`): paired by QR from Settings › Phone, token hashed, an allowlist of methods; conversations go to the phone in pages (`PhoneTail`), big fields cut. The phone reads a chat's changes read-only (`phone.changes`, `phone.diff` in `services/phone-changes.ts`: only files the chat folder's git status lists, or the chat's own edits) and sends reviews in the desktop's format. Phone 1.9 adds a Recent list with pins, a deck for what waits, search (`phone.search`), step screenshots (`phone.image`), per-chat notifications and app shortcuts; the phone's boundary checks live in `services/phone-guard.ts`. Phone transport (`services/phone-secure.ts`, `mobile/src/lib/secure.ts`): the desktop's P-256 identity (`<home>/phone-identity.pem`) is pinned by a fingerprint in the pairing QR; a signed ECDH handshake bound to the pairing secret, then every frame AES-GCM with a sequence number; files go over that socket in chunks (`phone.fileStart`/`fileChunk`/`fileEnd`, `services/phone-files.ts`; busy answers carry `retry` and `retryAfterMs`, the phone's `whileBusy`), only over the wire whose handshake proved the paired desktop (`conn.sealed()`), checked against the SHA-256 the share recorded (`ToolItem.handed`) before they are published or installed; names are made canonical once (`shared/file-name.ts`, checked again in `FilesPlugin.java`). Phones paired before stay on plain frames until they pair again. Wave 5 and 6 boundaries: a phone approval is limited to what the phone was shown (`core/permission-scope.ts`); every handler gets the guard of the pairing that sent it; long lists come in pages (`phone.sessions`, `phone.prompts` with cursors from `app.hello` and `PhoneTail`), read on by the phone's store, which replays list and prompt events that arrived meanwhile; a message taken back from the queue is kept on the phone first (`mobile/src/lib/take.ts`, `drafts.ts`) and leaves the queue on `phone.takeDone`; Forget moves the pairing's generation on (`mobile/src/lib/epoch.ts`: work begun before writes nothing back) and erases its storage (`erase.ts`, `forget.ts`). Containment of a chat's files (`core/contain.ts`): the handle's own path on Linux, two walks around the open on Windows and macOS (not a proof; its known gap is documented there). Remote Control is on by default per chat; `core/remote-keep.ts` limits how many idle agent processes stay for it.
  - Devices (`services/device.ts`, `providers/device-tool.ts`): `device_*` tools for an Android emulator or phone over adb (screenshot, tap, swipe, type, install, launch, logs).
  - Spare (`core/spare.ts`, `SessionMeta.spare`, `composer/SpareStrip.tsx`): "Continue at reset" on the limit notice, and `/spare <message>` holds a message in the queue until an account has weekly quota projected to expire unused (within caps, never credits, never a reset grant, at most two at once).
  - Long chats: a session file is a base plus a small tail (`core/session-file.ts`; the runtime reports changed items, so a save writes only the tail), and the window gets finished tool steps cut (`core/trim.ts`, cut at the socket in `bridge.ts`, `ToolItem.more`); `session.item` fetches a step whole when it is opened.
  - Turn check (`core/check.ts`, `timeline/Check.tsx`): "Check with Codex" (or Claude Code) under a finished turn with changes; the other agent reviews read-only as a child of the chat, its findings go to the composer.
  - Updates (`services/update.ts`, `update.*`, `UpdateState`): the desktop shell asks GitHub for the newest release, downloads its installer in the background (size and SHA-256 checked) and "Restart to update" (sidebar, Settings › About) runs it silently with `--force-run`; while agents work it waits. Dev and standalone bridges report `unsupported`.
  - Bypass (`bypassesAsking` in `providers/claude.ts`): in Bypass, Claude Code's own safety prompts are answered at once; switching a chat to a `danger` mode answers the prompts already waiting. Questions still wait.
  - Review comments (`src/features/review/`, `DiffView` `review` prop): comment on diff lines (Changes tab, applied edit steps); comments gather per chat in a bar above the composer and go as one message (`sendReview`).
  - Race (`core/race.ts`, `src/features/race/`, `SessionMeta.race`, `race.*`): `/race <task>` gives one task to two agents (or two models), each in a lane; the race view shows both side by side; "Keep this one" lands one lane and removes the other.
  - Project scripts (`services/scripts.ts`, `project.scripts`, `rail/scripts-store.ts`, `lib/dev-url.ts`): "Run" in the Terminal tab runs package.json scripts; a local URL a server prints offers "Open" in the Browser tab.
  - Search, export, saved prompts: `services/search.ts` (`search.messages`, shared with `phone.search`: bounded per call, reads chats not open from their files, resumes) feeds the palette's Messages section; `core/chat-markdown.ts` and `services/export.ts` (`session.markdown`, `session.export`) behind the session header's Chat menu; `services/prompts.ts` (`prompts.*`, `<data>/prompts.json`) for saved prompts in the palette, the `/` menu and Settings › Prompts.
  - Chat titles (`core/titles.ts`, `AppSettings.chatTitles`): after a chat's first successful turn its own provider and account name it with their smallest model (Claude: Haiku one-shot; Codex: a throwaway read-only thread); never a title the person set.
  - Previews (`services/thumbs.ts`, `electron/thumbs.ts`, `file.thumb`, `phone.thumb`): file cards show the real picture, PDF page or video frame (Electron's shell thumbnails passed in like the updater's host, Windows' PDF renderer as a fallback); the phone gets only the exact shared file (`ToolItem.handed`, `core/handed.ts`).
  - Start-up (`src/boot.ts`, `src/lib/boot.ts`, `server/util/boot.ts`): a tiny boot script opens the bridge and asks `app.hello` while the bundle loads and starts the launch light; the launch releases once home is there; the Agent SDK loads from `dist-electron/sdk.cjs` on first Claude use; `SABLE_BOOT_TRACE=1` prints the stages.
  - Keep awake (`core/awake.ts`, `keepAwake` in `electron/main.ts`): while a turn or an /until check runs anywhere, Windows does not suspend; released a minute after.
  - Profile (`services/profile.ts`, `providers/profile-tool.ts`): `<home>/profile.md`, the person's own text plus facts agents saved with `remember_about_user`; read into every session.
- Dev helper in the browser console: `sable.demo('refactor the session module')` opens a Demo session and sends a prompt (keywords pick scenarios, see `server/providers/demo-scenarios.ts`: refactor, plan, question, agent, search, markdown, error, mcp, long, hi; generative UI: chart, form, dashboard, diagram, table, widget, gallery, previews, whole, sandbox, escape; stress: marathon (a 300-step turn), tome (a 4000-line answer); notifications (the messages Claude Code writes into a chat: task notifications, slash commands, `!` output); `/compact`, `/context`). `SABLE_DEMO_SPEED` scales its pace. Demo accounts added in Settings sign in as made-up people with made-up limits. `sable.store.getState()`, `sable.actions`.

## Working rules

- Stay inside the files you were given. Shared files (`shared/`, `src/state`, `src/styles`, `src/ui`, `src/icons`, `src/art`, `src/app`) belong to the lead: add to them only when the brief says so; otherwise report what you need.
- This is a laptop that must stay responsive: no parallel heavy processes, no extra dev servers, kill what you start, no new dependencies without a strong reason (say so in your report).
- Verify visually with headless screenshots, not the Browser pane (it does not render while the display is off): `node scripts/shot.mjs --size 1280x800 --eval "<js>" --wait 1500 --shot scratch/<name>.png` (steps run in order: `--eval`, `--wait`, `--click "css"`, `--hover`, `--fill "css=>text"`, `--type`, `--key`, `--shot file[@css]`; see the header of that file), then Read the PNG. Each run starts on the home screen with a clean profile; open a session with `--eval "sable.actions.openSession(id)"` or start one with `--eval "await sable.demo('refactor the session module', {mode:'bypassPermissions'})"`. Page errors and console errors are printed by the script. One headless run at a time, write images only to `scratch/` (git-ignored), and look at your screenshots critically: spacing, alignment, hierarchy, states. Type-check before you finish.
- Real provider turns cost quota. Build and test against the Demo provider.

## Design language (read this twice)

The brief from the owner: far better looking than Claude Code's own app; modern, simple, clean; dark, calm panels over a rich backdrop; subtle background effects; colourful dither; rich detailed icons; beautiful motion; cinematic. He rejected the earlier tactile look (lit edges, gradient fills, bevels) as cheap: controls are quiet, flat and precise, premium through proportion, spacing and type. Explicitly forbidden: monospace uppercase labels, "eyebrow" kickers above headings, sloppy colours, generic AI-app look.

Newer guidance from the owner: really clean and professional. No descriptions in pickers and menus (expect people to know), no helper sentence that restates a label, no decorative colour on controls, no tags or badges that do not carry needed information, nothing extra on the home screen.

Latest guidance from the owner (21 Nov 2026): he lived with the liquid glass and tactile look of 20 Nov for two days and rejected it as built: a top edge brighter and thicker than the sides and bottom, bright corners, a sheen fading down from the top, a pane that goes light when clicked, bevels on controls. What floats stays glass, but calm, even and precise: one hairline rim that reads the same all the way round, a clean frosted fill, depth from the shadow alone. Controls are flat again: no skeuomorphism. He judges by details: a bright edge or a one-frame flash reads as cheap. Colour still only in the field and the agent marks.

- Monochrome: ink surfaces, ivory text. Surfaces are neutral near-black (`--bg` ground, `--sheet` stage, `--panel`/`-2`/`-3` each one step lighter, `--fill-*` for hover/selected, `--hl` for a highlighted row, hairlines `--line*`). Colour lives only in the backdrop (the dither field) and the agent marks, plus tiny meaningful marks: `--amber` waiting on you, `--red` error, green/red numbers in diffs. `--accent` is neutral ivory. No tinted icons or tiles, no coloured chips or buttons, never a hue as decoration, never new colours: use tokens.
- Depth: ink and light. In-flow surfaces (cards, panels, the timeline, plain buttons, fields) are flat; depth comes from layering (each layer one small step lighter) and from light that reacts. There is one light, from the top and slightly left; every highlight and shadow below agrees with it. Reactive hairlines: borders are almost invisible at rest and brighten near the pointer on any element with `data-spot` (cards, panels, menus, dialogs, the composer; `ui/spot.ts` runs the one listener and appends a `.spot-ring` span, so never write your own pointer listeners). Small accents use monochrome dither, never gradients: `.dither-sel` on a selected row's pill, `.meter` + `.meter-fill` (`--p`, `data-level`) for progress, `.skel` for skeletons. Controls: `.btn` is one fill step with an almost invisible hairline, hover one step lighter, press `scale: .97`; one solid ivory `.btn-primary` per view; fields are a darker well whose hairline turns soft ivory on focus (`--focus-field`); the focus ring is ivory at reduced strength (`--focus`).
- Glass (the material of what floats; tokens `--rim-*`, `--glass-*`, `--shadow-glass*` in `styles/tokens.css`, rules under "material: glass" in `styles/ui.css`, every state in the gallery's Material section). Where: the composer (home and dock), menus and popovers (`.pop`), dialogs (Settings, History, the folder picker, Add account, Before / after), the command palette, the quick switcher, the account switcher's limits beside its menu, the triage deck's cards and its end line, `.glass` (find bar, "Jump to latest"), toasts; another floating layer may wear `.glass-liquid` (an opaque pane with all of it) or `.glass-rim` (the rim alone, for a layer that keeps its own fill and sets `box-shadow: var(--rim-inner), var(--shadow-glass)` itself). Tooltips are opaque, with the same hairline and depth in one box-shadow (`--shadow-tip`). The person's message is a small pane of it without blur or grain (`.user-card::before`; its numbers repeat for the flying copy in `composer.css` `.send-surface` and `liquid-shape.ts` `INK`: change them together). Nothing else in flow, nothing that scrolls: a menu whose rows scroll puts the scroller inside the `.pop`, and hover bars inside the conversation stay flat (`--shadow-pop`). All static paint: (1) the fill: frosted ink in one even tone with the static grain (`--grain`) and a backdrop blur (`--blur`; opaque for dialogs and toasts, which never blur); (2) the rim, the surface's `::before` (so `::before` is taken): a 1px masked ring filled with `--rim-light`, the same strength on all four sides and round every corner; (3) `--rim-inner`: a faint glow just inside the rim, the same all round; (4) depth, `--shadow-glass`: a dark contact line, a near shadow and a wide soft one. Never a glint, a brighter top edge, a bright corner, a sheen or band fading down from the top (`--glass-sheen` is `none`, kept for rules that still name it), thinner edges, or a fade laid over glass (on a translucent pane it shows as a pale band). The reactive hairline on glass is the rim itself, a little brighter near the pointer (`--spot-glass`, weak and wide), never a second line; on the composer, wide and low, the whole rim steps up evenly with a touch more near the pointer. The composer (`composer.css`) is the main pane: `--glass-pane`, thin enough for the field's colour; on focus it draws no ring and never goes lighter: one layer under the content fades in by opacity (a little more ink, `--glass-pane-lift`; the hairline a step clearer all round; the deeper `--shadow-glass-lift`) and the placeholder steps back. Long text is cut at the field's edges. Rows, text and controls on glass stay flat. Rules: monochrome; never animate the rim or a shadow (fade a layer's opacity instead); when the governor sheds effects (`data-quality`) glass loses its blur and goes opaque.
- Flat controls (tokens `--press-*`, `--key-*`, `--thumb-up`, rules under "material: flat controls" in `ui.css`). The few controls with a fill of their own (the composer's attach disc and mode chip, a segmented control's pill, the selected row's pill, `.srow-pill` and `.dither-sel`, wherever a list has a selected row) are one fill step and one even hairline (`--press-up`). Hover is the next fill step, held one more with the small give in scale; open or on holds the hover step and the hairline steps up (`--press-down`). A bare chip (model, effort, the plain `.chip`) has no edge until it is held, open or on. Tracks (a switch, a segmented control) are a darker fill with the same hairline (`--press-well`); thumbs are flat discs with a short drop (`--thumb-up`). The send key is the one ivory key: a flat ivory face and a short soft drop (`--key-up`); hover goes to white, held it dims a touch and the drop shortens (`--key-down`) in the same frame as its give in scale; the stop key is the same key with a dark square and never moves; the compare slider's handle is the same key. Hairlines and drops swap in one frame with the state; nothing transitions them. Never a top light, an inner shade, a lip, a gradient face or a gloss: states read by fill and the give in scale (a menu's highlighted row is light, not a press). `.tactile` is only the old class name of a filled control.
- Type: Inter (variable, optical sizes; `--font-sans`) for the interface; Geist Mono (`--font-mono`) only for code, diffs, terminal output and inline code. Paths, folder names and commands shown as labels use the UI font with the directory dim and the name regular (`<PathLabel path>`, `.path`), never mono. 13px UI, sentence case everywhere, no uppercase or letter-spaced labels. Use the scale (`--t-*`) and weights (`--w-*`: 400/500/580); headings are 600 and tight (`.h1/.h2/.h3/.display`); figures that line up use `.num` (tabular). Small secondary text is `--text-2`/`--text-3`, never below 11.5px.
- Shape: radii from tokens (`--r-sm` 8 controls, `--r-md` 10, `--r-lg` 12 cards/menus, `--r-xl` 14 panels, 16 menus, 20 the composer). Controls are 30px tall with 13px text (`--t-ui`), composer toolbar controls 28px and fully round, menu rows 26 to 28px. Calm rhythm, a single column (`--column`) for reading.
- Icons: plain line icons, monochrome. `<Icon name>` (Phosphor regular; bold for tiny carets and checks) inline; `<Glyph name>` is the same plain icon in a fixed box for rows that need alignment (its `tone` only applies when it is amber or red). Icons answer their control on hover with one small move (icons.css). Never emoji. Add missing icons to `icons/index.tsx` using the per-icon Phosphor import pattern there.
- Motion: purposeful, fast, soft. Enter with a short rise + fade (never a blur filter), spring for things that move (`motion/react`, stiffness 380–520, damping 32–40), `--ease-out` for CSS. Durations from tokens (`--d-1..4`). Animate height when revealing details. Nothing bounces wildly, nothing loops except the working indicator (`<Tiles>`), `.shimmer` text and the dither field. Respect `prefers-reduced-motion`.
- Effects: the spectacle lives in the backdrop and at a few moments, never on controls. The field answers the app with one-shot beats (`fieldBeat(kind, el)` in `art/events.ts`, drawn in the worker, `FieldBeat` in `art/field.ts`): `send` (a pressure wave from the send key: thin crest that bends the pattern, a trough, an echo), `done` (a ring closes in on the composer as the turn's steps gather, then the band exhales), `fail` (the light dips and recovers), `pulse` (a softer wave for small moments). While a turn runs the field drifts quicker; waiting on you it stills (amber band). Strength follows the surface (full on home, restrained in a session, nothing when the backdrop is off, still or under reduced motion) and the backdrop's own amount, speed and reaction settings; no new switches. The pointer leaves a faint light that trails it on full stages. Rest: after 20 s with no input and no running turn the field eases to a still frame and stops drawing (no timer, no frame) until input or a beat wakes it. View changes use the dither veil (`veil(host, 'swap' | 'reveal' | 'cover')` in `art/veil.ts`): four quarter-tiles of the 4x4 ordered dither in the surface colour, stepped by opacity only, so content dissolves into the ground and resolves out of it (sparse, checker, solid, as the mark builds) on the compositor; 260 ms for a swap, the views only change opacity and transform, nothing reflows. The launch (`art/LaunchLayer.tsx`, light drawn in the worker by `art/launch-light.ts`): one cell ignites, a wake of dither thresholds builds the mark from its own cells, it holds while the bridge starts, then a crest opens the ink in dither order onto home while the mark glides to its place; a key or click yields at once and nothing is left running. The home mark glints a missing corner cell per keystroke. A send is one drop of liquid glass (`composer/flight.ts`, the path and springs in `liquid-shape.ts`, drawn in a worker with WebGL in `liquid-gl.ts`, 2D fallback): the words run as one piece into the bar's top-right corner while the field closes to one line, the bar rests empty for a moment, its edge swells and a drop pushes up through it on a thin thread that parts and snaps up into the drop (the bar's edge bobs once), the drop coasts to where the row lands, stretched along its speed, with a small highlight from the top left and the field refracted behind it (its only colour), lands still moving and wets out into the card, revealing the words in place (readable in about 320 ms, 380 from home), and the real row takes over. One path and one speed that never steps; time zero is the first frame the words show in; the key handler reads the page once and then only writes. The field's `send` wave starts where the thread parts and a softer ripple where the drop lands (`fieldBeatAt`). From home the composer leaves for the dock (`home/handoff.ts`) while the thread still holds; the queue gets the same drop as a hop into the tray row; steer and send now the same motion. Nothing is left behind at rest; under load the worker sheds the refraction and the soft shadow before frames; reduced motion is a calm fade. A steer leans in sideways, cools to the waiting tone, and a hairline wire ties it to the turn; when taken, a light runs along it. Streamed text is written at a zero-width write head (`.md-caret` in `components/Markdown.tsx`) whose short feather lifts off the newest words. Icons animate on hover or focus of their control (`icons/animated/`: Phosphor redrawn as parts, each icon its own one-shot motion of 200 to 450 ms ending on the rest pose, never a plain spin). Rules: every effect is one-shot and a few hundred ms (the field, `<Tiles>` and `.shimmer` are the only loops); colour only in the field and the agent marks; transform, opacity and worker canvas only (no `filter`, no animated `box-shadow`, no `mask-image` on live content); zero cost at rest; under load the governor sheds the effects (bending, echo, pointer light) before it lowers the frame rate. A moment that is not clearly better than nothing is removed.
- Density: quiet by default, detail on demand. Rows are one line until expanded. Secondary actions appear on hover/focus. Empty states are one calm sentence, no illustrations.
- Copy: plain, specific, short. Say what happens ("Allow once", "Rewind to here"), no exclamation marks, no filler, no em dashes, no marketing voice.
- Every interactive element needs hover, active and focus-visible states, an accessible name, and keyboard access. Show shortcuts with `<Kbd combo="mod+k">`.
- Performance is part of the design: streaming must never re-render settled items; subscribe narrowly to the store (`useStore(s => s.data[id]?.items[itemId])`), memoize, avoid layout thrash, keep animations on transform/opacity. `backdrop-filter` only on small floating layers and the composer; no `mask-image` on scrollers or animated content (use a gradient overlay pseudo-element in the surface colour; the static 1px rings of glass and of `data-spot` are the exception); no `filter` in animations or at rest; hover/press transitions on background-color, color, opacity or transform only, 80 to 120ms, never on box-shadow, border or size; menus open in about 120ms; `will-change` only while something animates.
